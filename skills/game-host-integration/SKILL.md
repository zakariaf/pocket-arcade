# Game host integration

Makes every Pocket Arcade game playable inside the one Shell: the typed game module enters through a single generic seam, the composition root builds every service once and provides the host, each run is saved before it is shown, runs end with stars and statistics recorded in one update before the result screen, and screens see only plain data. A script proves the host's files, its invariants, the composition root, the Tutorial route, the Game screen and each game's assembly.

## Rules that must hold

1. **`createGameHost<T>(game, deps)` is the only place the Shell touches a game's own types.** Screens, UI, stores and navigation use the type-erased `GameHost`, `SessionHandle` and `SessionView`; no casts anywhere in `game-host/`. Why: TypeScript cannot store "a module of some type" without casting, and a cast hides exactly the errors the owner relies on the compiler to catch.
2. **Every change is reduced, saved, then published.** The session store's persist step writes the run (or records its end) before any subscriber, board or screen sees the new session. Why: spec 8.6 and S5, killing the app mid-animation must reopen the exact same state.
3. **Only the game's `intentToMove` makes moves; `null` means nothing happens.** The host never builds a move itself, and the reducer ignores moves while paused or finished; the tutorial run also ignores a legal move its current step does not expect. Why: bots, solvers and players then share one legality, and no illegal state can be saved.
4. **A run ends in ONE save update with the backup refreshed, before S7 appears,** written through `writeRunEnd` (the composition root's `updateAndPublish`, so the stores re-read it): `applyRunEnd` plus any `extendRunEnd` section, stars from the level's table rule through `starsFor`, counters by replaying the kept move line. The deciding move then plays `playUiFeedback(feedback, isWon ? 'win' : 'lose')` once. Why: spec S7 and 8.1, a result on screen that is not on disk breaks trust and streaks.
5. **One continue per run, only after a loss, only when the game has one and `game.config.ts` allows it** (`continueStateOf`, `isContinueAllowed` from the game's config, never a literal); `isContinueAllowed` is true exactly when `rules.continueRun` is `{ kind: 'once' }`, and `hints.freePerDay` is 0 when `rules.hints` is `{ kind: 'none' }`. An offered loss stays pending (saved) until the player continues or declines. Why: spec 8.10; a Continue or a free hint the rules cannot honour is a button that does nothing.
6. **A saved run is validated by the game's own parsers at boot and on resume;** an unreadable run is dropped alone and logged, a replay that differs keeps the position and drops only the undo history, and a resumed run starts paused. Why: spec 8.6, S14 and S5; one damaged run must never cost progress or crash the app.
7. **The composition root is this skill's template, `packages/shell/src/app/`:** `createShellParts` hydrates the save, creates the host right after it (before the stores and the resume state) with `feedback: debugFeedbackOf(...)` (the debug parts' recorders in test builds, the E2E evidence of the win sound and success pulse) and `createBoardHost: createGameBoardHost(...)`, calls `connectPremiumReloads` right after `startPremium`, and `ShellFeatures` provides `<GameHostProvider>`. Why: the host may drop an unreadable run that must never be resumed, and the store price must load once the first network state arrives.
8. **The Game screen opens its run with `useGameSessionControls(route.params)`, renders `controls.BoardHost`, and calls `usePauseOnBackground`.** Why: spec S5, going to the background pauses and coming back shows Pause, never a running game.
9. **Paid perks are sent to the run only after payment:** the price comes from the ads layer's `perkOffer`, a free hint spends the daily allowance, a hidden offer hides the button. Why: spec 8.5, 8.8 and 8.10; a hint or continue given before a completed ad is a free perk forever.
10. **A tap-then-tap selection is UI state of the board host, never a move:** a tap in one of `engine.selectRegions` toggles it (announced to VoiceOver), the next tap reaches `intentToMove` with `selected` filled in, and any applied, undone or continued move, a restart, the run end or a drag clears it; the board draws it and the bought hint from its `highlight`. Why: bots, sims, the witness solver, par, undo and the move counters must never see a selection.
11. **`apps/<game-id>/src/index.ts` is assembly only (one typed constant with all eleven members, `identity: { id, nameId, winTitleId, taglineId }`) and `apps/<game-id>/index.ts` is exactly the 3-line entry.** Every game runs `contract.test.ts` and a teaching script whose expected moves are legal, with 3 to 5 how-to-play pages and every key in all four catalogs. Why: the owner never reads code; these tests are the proof that the game fits the Shell.
12. **Screens get the game only from the host:** `nameId`, `winTitleId`, `taglineId`, `logo`, `credits`, `hasMusic` (the S6 and S11 Music rows), `isScoreRated` (the S7 score line) and `hasHints` (the S5 hint key), all three from `game-facts.ts` (`hasMusicOf`, `isScoreRatedOf`, `hasHintsOf`, the rules the parity reference variants use too), `counters` (S10 cards: `{ id, labelId, aggregate }`, a max counter shown as ×N), `packs` (S8), `howToPlayPages`, `renderHowToPlayPicture` and `howToPlayPictureAspect` (S13: 320 / 206 unless the board gives `exampleAspect`), `tutorialSteps`; the board gets `panMode` and `selectRegions` from the engine. Why: the module is the single source; a screen that imports an app or hard-codes a title breaks the next game.
13. **Test builds end, open and dress runs only through `host.debugControls()`:** `playTo` swaps in the game's win or lose example and ends the active run, a level, today's daily or an endless run, through the same persist step as a deciding move (stars, the daily result and streak, the endless best, statistics and the ad history saved before Result shows), `openExample` opens level 1 at an example state, and the parity frames get the design's numbers from `applyFixtureHud` and `showFixtureResult` (never saved). The composition root hands them to `createDebugParts` only, which store builds never get. Why: the per-game E2E flow (`action=win-level`) and the S5-S7 parity frames must see the real run-end path and the real Result, not a shortcut that skips the save.

## Workflow

1. **Check what exists.** From the repo root run `node ${CLAUDE_SKILL_DIR}/scripts/check-game-host.mjs .`. Each `prerequisite-missing` line names the skill that builds the file (the host only wires existing parts): build those first. A partial Shell (`shell-slice.json`) turns the rules of screens outside the slice into `SKIP` lines. Read [references/host-architecture.md](references/host-architecture.md) for the seam, the file owners and the path of one move.
2. **Install the host once per repo.** Copy `templates/packages/shell/src/game-host/` to `packages/shell/src/game-host/`, and `templates/packages/shell/src/testing/` (`tally-game.ts`, `create-test-adapters.ts`) to `packages/shell/src/testing/`, verbatim. Run `npx tsc --noEmit -p packages/shell` and `npx jest packages/shell/src/game-host --ci --selectProjects unit --coverage --collectCoverageFrom='packages/shell/src/game-host/**/*.ts' --coverageThreshold='{}'` (paths first; only `npm run test:coverage` judges the thresholds): every host behaviour is proven against the tally game.
3. **Install the composition root.** Read "The composition root" in host-architecture.md. Copy `templates/packages/shell/src/app/` to `packages/shell/src/app/` verbatim: `create-shell-app.tsx`, `create-shell-parts.ts` (with `recordAdLevelEnd`: every finished level counts in the ad history in the one run-end update), `debug-switches.ts`, `device-adapters.ts`, `create-premium-deps.ts`, `connect-premium-reloads.ts`, `shell-app.tsx`, `shell-features.tsx`, `shell-navigator.tsx`, `load-outcome-opener.tsx` (the S14 dialog the save's load outcome asks for) and their tests. `hydrate-save.ts` and `use-checkpoint-on-background.ts` come from save-persistence-and-migrations, `create-debug-parts.ts` from e2e-maestro (it gets `game: host.debugControls()`), the consent moment `consent-moment.tsx` (with its context and hook, mounted in `ShellFeatures`) from admob-ads with toybox-screens' `screens/consent/consent-intro-screen.tsx`, and `NavigationRoot`'s `navigationRef` and `onReady` props (the debug link handler starts there) from navigation-and-routing; the table there names the skill behind every other import. In a partial Shell every Shell-core file stays in (host-architecture.md, "In a partial Shell"). Add the two board announcement keys ("Texts the host adds" in host-architecture.md) to the Shell catalogs in all four languages. Run `npx jest packages/shell/src/app --ci --selectProjects unit --coverage --collectCoverageFrom='packages/shell/src/app/**/*.{ts,tsx}' --coverageThreshold='{}'`: `shell-app.test.tsx` renders Settings and the tutorial through the real providers, so a provider the root forgets fails here. In the Shell build order the root lands at step 7, while every route is still a `NotBuiltScreen` stand-in: copy `shell-app.test.tsx` with S11 Settings at step 9, because its tests need that screen.
4. **Install the Tutorial route.** Copy `templates/packages/shell/src/screens/first-run/` (`tutorial-screen.tsx`, `tutorial-view.tsx`, `use-tutorial-model.ts`, `tutorial-coach.ts` and their tests). navigation-and-routing's `root-stack.tsx` registers it as the FirstRun route `Tutorial` (`gestureEnabled: false`); its `tutorial.*` texts come from the copy deck (i18n-strings-and-catalogs, S13). The Tutorial route is part of the Shell core: it is always installed and routed to `TutorialScreen`, whatever `shell-slice.json` holds (S13 How to play may be outside the slice; the route never is), so `shell-app.test.tsx`'s first launch reaches `tutorial.screen` in every slice.
5. **Wire the Game screen.** Its view side ships in toybox-screens (the Shell's one `screens/game/game-screen.tsx`, the same bytes as [examples/game-screen/game-screen.tsx](examples/game-screen/game-screen.tsx), with its model hook, `GameLayout`, `GameTopBar`, Pause and Result); this skill wires the host into it: `useGameSessionControls(route.params)`, `controls.BoardHost`, `usePauseOnBackground`, `topBarPropsOf`, `resultModelOf({ view, game: useGameHost(), ... })` with `RunText.gameText = (message) => gameMessageText(t, message)` (i18n-strings-and-catalogs), and perks paid for with `perkOffer(useHintPerk(today), ...)` before `hint` or `continue` is sent. In a parity capture the session-controls hook opens the S6 and S7 frame states itself (host-architecture.md, "Test builds").
6. **Assemble each game.** Read [references/assembling-a-game.md](references/assembling-a-game.md). Copy `templates/apps/__GAME_ID__/` to `apps/<game-id>/` and `templates/test/integration/game-host/__GAME_ID__-debug-controls.test.ts` to `test/integration/game-host/<game-id>-debug-controls.test.ts`, renaming files and replacing `__GAME_ID__`, `__GAME_PASCAL__`, `__GAME_CAMEL__`, `__GAME_CONST__`; imitate architecture-and-boundaries' Line Siege module for a real game. `GAME_ART` comes from code-drawn-art-and-icons. Write the teaching test first, then the teaching script. Add the teaching keys and `<game-id>.win-title` to all four catalogs (compare [examples/tap-flip/i18n/en.json](examples/tap-flip/i18n/en.json)). Set `game.config.ts` `isContinueAllowed` and `hints.freePerDay` from the rules (rule 5). Switch `index.ts` to the 3-line entry last.
7. **Format, lint and type-check:** `npx eslint --fix` and `npx prettier --write` on the changed files, then `npx tsc --noEmit -p packages/shell`, `npx tsc --noEmit -p apps/<game-id>` and `npx eslint --max-warnings 0` on them.
8. **Run the tests:** `npx jest packages/shell/src/game-host packages/shell/src/app packages/shell/src/screens/first-run apps/<game-id>/src/contract.test.ts apps/<game-id>/src/tutorial test/integration/game-host --ci --selectProjects unit --coverage --collectCoverageFrom='packages/shell/src/{game-host,app,screens/first-run}/**/*.{ts,tsx}' --coverageThreshold='{}'`.
9. **Run the check** `node ${CLAUDE_SKILL_DIR}/scripts/check-game-host.mjs . --game <game-id>`; fix every `FAIL` line (each names the file, the rule and the fix) and rerun until it prints `RESULT: PASS`.
10. **Get device evidence and report.** The kill test (move, kill during the animation, relaunch lands paused in the same state) and a full level to the result screen run on the simulator with the ios-simulator-build and e2e-maestro skills. Report in players' words what works, what was verified and what still needs the owner (ads, purchases, feel on a device).

## Definition of done

- [ ] `packages/shell/src/game-host/` holds every template file with its test (the board host factory and the selection hook included); the game-host Jest run passes.
- [ ] `packages/shell/src/app/` holds the composition root templates with their tests: the host after `hydrateSave` and before the stores, the resume state recomputed after it, `connectPremiumReloads` after `startPremium`, `<GameHostProvider>` in `ShellFeatures`; `shell-app.test.tsx` passes through the real providers.
- [ ] The Tutorial route files and tests are in `packages/shell/src/screens/first-run/`, in every slice (Shell core).
- [ ] `host.debugControls()` reaches `createDebugParts`: `playTo` ends the active level, daily or endless run through the run-end path (stars, the daily streak, the endless best and the ad history saved before Result), `openExample` opens level 1 at an example, and the parity frames open S6 and S7 with the design's numbers; `test/integration/game-host/<game-id>-debug-controls.test.ts` passes.
- [ ] A decided run plays `ui.win` + `success` or `ui.lose` + `error` once, an endless run above its best shows "New best!", a score-rated level's win model has no par and carries the level best (`bestScore`, the S7 score line), and every finished level counts in the ad history in the same save.
- [ ] The Game screen opens its run with `useGameSessionControls`, renders the board host, pauses on background and blur, shows the top bar and result from `topBarPropsOf` and `resultModelOf`, and sends `hint` and `continue` only after payment.
- [ ] Each game has its types bag, the assembled `src/index.ts`, `GAME_ART`, the teaching script with its test, `contract.test.ts` passing, a `game.config.ts` that matches its rules, and the exact 3-line `index.ts`.
- [ ] `npx tsc --noEmit`, `npx eslint --max-warnings 0` and `npx prettier --check` pass for `packages/shell` and `apps/<game-id>`; no `__GAME_` placeholder is left.
- [ ] The simulator kill test reopens a killed run paused in the same state, and a finished level shows its stars after they are saved.
- [ ] `node ${CLAUDE_SKILL_DIR}/scripts/check-game-host.mjs . --game <game-id>` prints `RESULT: PASS`

## Anti-patterns

- **`game as unknown as ShellGameModule<ShellGameTypes>` to store the module in a context.** Close over the typed module in `createGameHost` and pass the erased `GameHost` instead.
- **Animating first and saving in an effect afterwards.** A kill during the animation loses the move; the persist step runs inside the store's dispatch, before `set`.
- **Writing stars, the daily result and statistics in three updates, or after S7 mounted.** One `applyRunEnd` update with `refreshBackup: true`, then show the result.
- **Recording a loss the moment it happens when a continue is offered.** Keep it pending; record on `finish` or `leave`.
- **Calling `applyMove` from the Game screen or the board.** Send `{ type: 'intent', intent }`; the host asks `intentToMove`.
- **A `select` move in the rules for tap-then-tap.** The selection is the board host's; `intentToMove` gets it as `intent.selected`.
- **Resuming from `hydrated.initialState` computed before the host ran.** Recompute `resumeState(save.doc())` after `createGameHost` (`initialStateFor` in `create-shell-parts.ts`).
- **Starting the store with `startPremium` and nothing else.** It runs before the first network state; without `connectPremiumReloads` Settings never shows a price.
- **A context provider written for one screen and never mounted.** Screens read host fields (`hasMusic`, `counters`); the render test through `ShellApp` catches a missing provider that `renderWithShell` would hide.
- **Sending `hint` and then showing the rewarded ad.** Pay first; send only when the ad completed, the allowance was spent, or the player owns Premium.
- **Logic in `src/index.ts`, or a 4th line in the entry.** Put logic in the part's own file with its tests; the entry is three statements.
- **Screens importing `@e07/<game-id>/...`, or playing `ui.win` from the Result screen's effect.** The Shell reaches a game only through the module; the host plays the result sound once for the deciding move.
