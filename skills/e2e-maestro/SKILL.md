# End-to-end flows with Maestro

Every Pocket Arcade game proves its wiring on a real Release simulator build: Maestro 2.10.0 flows drive the Shell's journeys and the game's own level, the app is shown to make no network traffic, the simulator cold start, memory and 200 % text are measured in the same run, and every screen is captured in 4 languages × light/dark × phone/tablet against committed baselines. This skill sets up that tooling, writes the flows, runs them, and its scripts prove the set-up, the flows and each run's reports.

## Rules that must hold

1. **Install Maestro only with `packages/tooling/scripts/install-maestro.sh`** (2.10.0 zip from GitHub, SHA-256 `29b675e1…d991` checked, into the ignored `tools/maestro/`), and run it with Java 17 and `MAESTRO_CLI_NO_ANALYTICS`, `MAESTRO_CLI_ANALYSIS_NOTIFICATION_DISABLED`, `MAESTRO_DISABLE_UPDATE_CHECK` set to `true`. Why: Homebrew and `curl | bash` are unpinned, and by default Maestro sends analytics and checks for updates.
2. **Run flows only through `npm run e2e:ios -- --app <game-id>`, against a Release simulator build of the `test` variant with ads off, on dedicated named simulators** (`e07-e2e-phone`, `e07-e2e-tablet`, `e07-shots-phone`, `e07-shots-tablet`, or this session's `e07-<purpose>`), never `booted` or another agent's device. The runner refuses any other build (`requireAdsOffTestBuild`): with ads off the app never asks Google's consent form or Apple's tracking prompt. The evidence run has four steps: flows, cold start, memory (with the feedback evidence) and large text; `--flows-only` is for iterating and is never evidence. Why: debug builds talk to Metro and ads open sockets on purpose, which hides a real leak; other agents' simulators get broken.
3. **Every Maestro run names its simulator and its own driver port, before the command**: `maestro --device <udid> --driver-host-port <port> test ...`, built in code with `maestroGlobalArgs` (`packages/tooling/src/e2e/maestro-args.ts`) and a free port per run (`freeDriverPort()`, or the session's `--driver-port`); never the per-command `--udid` alone and never the default port 7001. Every `simctl` call names the UDID. Why: in round 3 another session's XCTest driver answered a run that named this session's simulator.
4. **Select elements by `id:` only, with ids from the testID contract** (`assets/screen-testids.json`, `assets/e2e-testids.json`, or the game's `apps/<game-id>/e2e/testids.json`). Text selectors are allowed only for OS-owned UI, under a `# system-ui: <why>` comment. Never select a crop-only part (the map's `parent` or `a11yHidden` entries, such as `levels.level-tile.1.stars-3`): Maestro lists only accessible elements, so select the `coveredBy` element and match its label with `text:`. Why: flows must run unchanged in en, de, fa and ckb, and an unknown or unreachable id should fail before a simulator waits 15 s for it.
5. **Start each flow with `launchApp: { clearState: true }` and set state only through `subflows/debug-setup.yaml`** (the test build's `<scheme>://debug/setup?...` link, `QUERY` + `WAIT_FOR`; it waits for a screen root first, so one link right after the launch works, `firstRun=0&...&screen=game` included; it accepts Apple's "Open in “<app name>”?" alert guarded on that title, never a bare `'Open'`, which also matches an ad banner's "OPEN" button: `check-flows` rule `open-alert-guard`). Send `action=` in a link of its own once the run is on screen (it ends any active run: a level, today's daily or an endless run). Never `openLink` in a flow and never tap through menus to reach a state; the one tap allowed is the key under test on the screen the link opened (S9's Play key, Home's endless card, the Result's continue key, the level-2 tile). Why: setting up through the UI is slow and flaky, and it ties every flow to every screen.
6. **Every `smoke` flow ends with `runFlow: <…>/subflows/assert-no-network.yaml`, and the run's `network.txt` is empty.** Why: spec N3 says the app's own code never uses the network; iOS simulators have no airplane mode, so the JS guard counter (`debug.network-attempts` = `0`) and the socket sampler are the offline proof.
7. **Never give a flow an `env:` block for `APP_ID`, `APP_SCHEME`, `LANG` or `THEME`.** Why: in Maestro 2.10.0 the flow's `env:` value wins over `-e` (verified), so every run would silently use the flow's value.
8. **Flows live in `<workspace>/e2e/flows/<area>/<nn>-<name>.yaml`** (Shell `01`-`09`, games `10`+), shared steps in `packages/shell/e2e/subflows/`, the matrix in `packages/shell/e2e/screenshots/`, and the premium-purchase skill's Tier 2 StoreKit flows (tag `storekit`, no `clearState`) in `packages/shell/e2e/storekit/`, which only its harness runs. Why: Maestro runs only the top-level files of a folder it is given, so a nested flow never runs and a sub-flow under `flows/` runs on its own and fails.
9. **No AI commands and nothing that uploads** (`assertWithAI`, `assertNoDefectsWithAI`, `extractTextWithAI`, `maestro test --analyze`, `maestro cloud`, `maestro login`, `maestro record` without `--local`). Why: they send screenshots or the run to a third-party service.
10. **A flaky flow is a bug**: wait on ids (`extendedWaitUntil`), never sleep; no `retry:` around app steps; a non-smoke flow may be quarantined for at most 7 days with `# quarantine YYYY-MM-DD: <reason>`; a `smoke` flow is never quarantined. Why: retries and sleeps hide timing bugs players will hit.
11. **Screenshots come only from a still, deterministic screen**: status bar 9:41, `reduceMotion=1`, ads off, seed 42 and date 2026-09-26, iPhone 17 Pro Max and iPad Pro 13-inch (M5) on iOS 26.5, tolerance 0.2% of pixels. Never raise the tolerance. Why: an animating screen differed by 1.08% between two captures one second apart (verified).
12. **Baselines change only on purpose**: `--update` for the sets you mean, every new or changed PNG (and its diff) opened with the Read tool, then a commit with a `Gate-Change:` trailer. The same holds for `perf-baselines/cold-start-sim-<game-id>.json` (`--write-perf-baseline`). Why: an unread baseline freezes a bug for every later run.
13. **The debug switches and the debug link reach services only through `debug-services.ts`**: `offline=0|1` flips the `SimulatedConnectivity` the whole app was built with, so every ConnectivityPort subscriber hears it; `date=YYYY-MM-DD` sets the `SimulatedClock` the whole app was built with (only `today()` moves); `premium=0|1` writes the save, then dispatches `debug-premium-set`; `geo=eea|other` (`setConsentGeography`) resets Google's UMP answer (ads on only) and the composition root's consent port (`services.consentFor(port)`) asks UMP with that geography from the next consent moment on; a debug consent port comes from `createConsentPort`. Why: a flip only the debug screen sees leaves the store, the ads and S12 in the old state, and a UMP call in an `ADS_MODE=off` build fails the network check.
14. **One path for the link and S15: `debug-link-handler.ts`** (`handleUrl` for links, `apply` and `importSave` for S15's tools). It listens to `Linking` from `createDebugParts` on and queues links until the navigator's `onReady` calls `start(Linking)`; a save write that switches the navigator's group opens `screen=` on the next navigation state. The flags outside the save live in the test-only key-value store (`debug.overrides`, `debug.pending-screen`). Why: a link sent while nothing listened is lost (round 2: every first link after `clearState`), a screen opened before its group is mounted never opens, and a flag held only in memory is lost at the direction reload and after `killApp`.
15. **The level-1 flow proves the real board, then wins through the game host.** One real move by taps (from `print-level-line.ts`), a kill and relaunch that resumes it, then `action=win-level` (`GameHost.debugControls().playTo`), asserting the stars the game's example win earns (`result.stars-<n>`, listed in the game's `e2e/testids.json`), then Levels shows those stars on `levels.level-tile.1` and the level-2 tile opens level 2 (`progress-after-win`). Why: taps prove input and persistence; the host's one run-end path proves stars are saved like a real win, without a hand-typed 12-move line.
16. **Each game mode has its flow** (`check-flows` rule `mode-flows`, read from `game.config.ts`): `modes.daily` plays today's daily and checks the streak the next day (`journeys/11-daily.yaml`), `isContinueAllowed` continues after a loss with the Premium continue (`12-continue-premium.yaml`; the rewarded continue is admob-ads' ads-on smoke test), `modes.endless` loses an endless run as an ads-off player without Premium (`premium=0`, never `premium=1`) and sees the endless result with New best at once, with no continue offer, then Home's best (`13-endless.yaml`; lead decision L11: never strand a finished run, `hidden` always means unavailable). Why: the daily, continue and endless paths have their own saves and screens that a level flow never reaches, and a run nothing can rescue must still end.
17. **The evidence run proves the win feedback was asked for**: `reports/e2e/<game-id>/feedback.json` holds the win sound and the success haptic from the perf log (`check-e2e-report` rule `feedback-evidence`). Why: Jest fakes prove the wiring and the WAV preview the sound, but only this shows the simulator app asked for them; how they sound and feel stays the owner's own check (never waited for).
18. **The evidence run proves S15's save benchmark**: smoke flow `04-debug-performance.yaml` runs "Run save benchmark", the runner keeps the entry in `save-benchmark.json`, `check-e2e-report` (`save-benchmark`) needs 300 writes and p95 under 5 ms. Why: otherwise the budget is measured only in Jest.
19. **S15 keeps design parity (L12, L13)**: `use-debug-model.ts` opens `debug-ads-always-test` once on mount through the "Always show test ads" switch's handler, reading `parityFrameState()` from `app/parity/parity-session.ts` (never `useParityOpener`: an import loop through the gate), and formats its numbers in the language's digits (never `String(n)`); labels stay English. Why: the frame draws the switch on and Persian digits.
20. **admob-ads' `packages/shell/e2e/ads-smoke/` flows run by hand** on an `ADS_MODE=test` build started with `xcrun simctl launch` (Maestro's `launchApp` grants the tracking answer), `geo=` in their first link; `check-flows` checks them, the runner never lists them. Why: they need ads on and the real prompts.

## Workflow

1. **Check the set-up** from the repo root: `node ${CLAUDE_SKILL_DIR}/scripts/check-e2e-setup.mjs .`. For each missing file copy the template of the same path from `templates/` (installer, runner and its perf steps, simulator helpers, gallery, comparator, socket sampler, `print-level-line.ts`, sub-flows, matrix, and the S15 debug kit: network guard, debug services, link handler with its inbox `debug-link-intake.ts`, overrides and key-value store adapter, save import, S15 model hook, with every test). The perf layer the cold-start, feedback and benchmark steps read comes from performance-budgets (JS half at Shell step 7, native half at step 8; rule `perf-layer`, runner reference). The debug kit is Shell core, installed with the composition root at Shell step 7 whatever the slice (`app/create-debug-parts.ts`, `debug-services-context.tsx`, `debug-link-*.ts`, `screens/debug/` without `use-debug-model.ts`, with their tests; not-yet-due `SKIP` lines before step 7); only `use-debug-model.ts` and the sub-flows wait for S15 (`SKIP` lines while S15 is outside `shell-slice.json`). `npm run e2e:ios -- --help` lists every runner option (`e2e-cli.ts`). Add the two npm scripts and the exact pins `pixelmatch` 7.2.0, `pngjs` 7.0.0 and `@types/pngjs` 6.0.5, and make `.gitignore` list `/tools/` and `reports/`. Read [references/maestro-setup.md](references/maestro-setup.md) and [references/runner-and-network.md](references/runner-and-network.md) the first time, and whenever the install or the runner fails. Wire the kit as "Wiring" in [references/debug-deep-link.md](references/debug-deep-link.md) shows: the composition root calls `createDebugParts(...)` (network guard first, then the perf log, the recorders, the debug services and the link handler, listening to `Linking` at once), plays the Shell's feedback through `parts.feedback`, asks for its consent port through `services?.consentFor(port)`, the app root provides `DebugServicesProvider`, and the navigator starts the handler from `onReady`. `use-debug-model.ts` is the hook toybox-screens' `debug-screen.tsx` renders; copy it after that screen and `app/use-game-extra.ts` exist. If neither `/usr/libexec/java_home -v 17` nor Android Studio's JBR gives Java 17, stop and ask the owner to install a Java 17 JDK.
2. **Get the build**: a Release simulator app of the test variant with ads off, `npm run build:ios:sim -- --app <game-id> --variant test --ads off` (building belongs to `ios-simulator-build`). The runner finds it in `apps/<game-id>/build/dd/Build/Products/Release-iphonesimulator/`.
3. **Write or change a flow**: read [references/flows.md](references/flows.md) once per session, and [references/debug-deep-link.md](references/debug-deep-link.md) for every `QUERY` parameter.
   - Shell journeys: copy from `templates/packages/shell/e2e/flows/` (`smoke/01-first-launch.yaml`, `journeys/02-core-journey-offline.yaml`, `rtl/03-language-switch.yaml`, `smoke/04-debug-performance.yaml`) at Shell step 10, once every screen they reach is built (in a partial Shell `check-flows` prints `SKIP ... [slice]` for them).
   - A game: run `node --disable-warning=MODULE_TYPELESS_PACKAGE_JSON packages/tooling/src/e2e/print-level-line.ts --app <game-id> --level 1`, then copy `templates/apps/__GAME_ID__/e2e/flows/smoke/10-level-1.yaml` to `apps/<game-id>/e2e/flows/smoke/10-level-1.yaml` and fill `__GAME_ID__`, `__GAME_NAME__`, the region ids, rows and columns of the printed first move and `__WIN_STARS__` (the stars `action=win-level` earns, also printed). List `result.stars-<n>` with that reason in `apps/<game-id>/e2e/testids.json`. Without the host's `debugControls` yet, play the printed bot line by taps instead (flows reference, "The level-1 flow").
   - The game's mode flows: copy `templates/apps/__GAME_ID__/e2e/flows/journeys/11-daily.yaml` (when `modes.daily`), `12-continue-premium.yaml` (when `isContinueAllowed`) and `13-endless.yaml` (when `modes.endless`) and fill `__GAME_ID__` and `__GAME_NAME__` (flows reference, "A game's mode flows").
   - An id the game adds only for flows goes into `apps/<game-id>/e2e/testids.json` in the same change as the code that renders it. No `: ` inside an `evalScript` (YAML reads a mapping): use arithmetic such as `Number(cond)`.
4. **Check the flows without a simulator**: `node ${CLAUDE_SKILL_DIR}/scripts/check-flows.mjs .` and fix every `FAIL` line (file, rule, fix). Once Maestro is installed, add `--syntax` (Maestro's own `check-syntax`, about 3 s per file). A repo with no flow yet passes with a `SKIP ... [flows-missing]` line while `shell-slice.json` marks a partial Shell; without that file the flows are due and `flows-missing` fails.
5. **Run them**: `npm run e2e:ios -- --app <game-id>` (add `--sim <purpose>` to use this session's own `e07-<purpose>` simulator, and `e07-<purpose>-tablet` for the iPad's large-text step; `--driver-port <n>` only when the session must hold one port; when a boot fails for lack of resources, shut down only your own `e07-*` simulators, never another session's): the flows (then `save-benchmark.json`), 6 cold launches against `perf-baselines/cold-start-sim-<game-id>.json` (the first run writes it: commit it with a `Gate-Change:` trailer), the game's smoke flow with `feedback.json`, a relaunch and `footprint` (≤ 150 MB), and the `a11y` flows at 200 % text in en and fa on phone and iPad. While iterating, `-- --flows-only --include-tags smoke` is fine; the evidence run has no filter. Then run `node ${CLAUDE_SKILL_DIR}/scripts/check-e2e-report.mjs . --app <game-id>`. For a failure, open `reports/e2e/<game-id>/` and rerun that flow alone; if it then passes it is flaky (flows reference, "Flaky flows and quarantine"). A line in `network.txt` is a spec N3 bug: find the code that opened it. Open every screenshot under `reports/e2e/<game-id>/large-text/` with the Read tool (clipping, overlap, rows that should stack).
6. **Screenshot matrix** (after any UI change and before a release): read [references/screenshot-matrix.md](references/screenshot-matrix.md). `npm run screenshots:ios -- --app <game-id> --sim <purpose>` (first time, or for an intended change: `--update` narrowed with `--devices` and `--langs`). Open every new or changed PNG and its diff with the Read tool: check direction, clipping, overlap, truncation and colours. Then run `node ${CLAUDE_SKILL_DIR}/scripts/check-e2e-report.mjs . --app <game-id> --screenshots` and commit the baselines with `Gate-Change: <which screens and why>`. For a new or redesigned screen, run the design parity check (`toybox-visual-parity`) before accepting its baseline.
7. **Before a release**: add the screenshot matrix at 200 % text (`--text-size accessibility-extra-extra-extra-large`, checked by eye) and run `check-e2e-setup.mjs . --baselines` (all 16 device/language/theme sets).
8. **Report and clean up**: paste the `evidence:` lines that `check-e2e-report.mjs` prints (flows passed, quarantined, network, screenshots) into the report, with at most five gallery rows worth the owner's look. For a release, open `reports/screenshots/index.html` for the owner. Shut down the simulators the run created (`xcrun simctl shutdown <udid>`, `e07-*` only).
9. **Rerun the checks** until each prints `RESULT: PASS`.

## Definition of done

- [ ] Every new flow is in `flows/<area>/<nn>-<name>.yaml`, selects by id, sets state through `debug-setup.yaml`, and was seen passing on the simulator.
- [ ] The debug kit's and the tooling's Jest tests pass (`npx jest packages/shell/src/screens/debug packages/shell/src/app/debug-link-handler.test.ts packages/shell/src/app/debug-link-intake.test.ts packages/shell/src/app/create-debug-parts.test.ts packages/shell/src/app/debug-services-context.test.tsx packages/tooling/src/e2e test/integration/save/sqlite-kv-debug-store-adapter.test.ts --ci --selectProjects unit --coverage --collectCoverageFrom='packages/shell/src/screens/debug/**/*.ts' --coverageThreshold='{}'`), a `lang=fa&date=...&offline=1&screen=levels` link lands on Levels after the reload with the date and offline flag still set, and one link after `launchApp: { clearState: true }` on a fresh install (`firstRun=0&level=1&boardLayout=1&screen=game`) opens Game.
- [ ] `npm run e2e:ios -- --app <game-id>` passed with no tag filter and without `--flows-only` (13-endless included), no smoke flow is quarantined, and the large-text screenshots were read; `check-e2e-report` judges the rest.
- [ ] Every Maestro line of the run log names this session's simulator and its own driver port (`maestro: device <udid>, driver port <port>: ...`).
- [ ] After UI changes, `npm run screenshots:ios` ran, every changed PNG and its diff was opened, and every baseline change has a `Gate-Change:` trailer. The tolerance is unchanged.
- [ ] Simulators the run created are shut down, and nothing ran on another agent's simulator.
- [ ] `node ${CLAUDE_SKILL_DIR}/scripts/check-e2e-setup.mjs .` prints `RESULT: PASS` (with `--baselines` before a release).
- [ ] `node ${CLAUDE_SKILL_DIR}/scripts/check-flows.mjs . --syntax` prints `RESULT: PASS`.
- [ ] `node ${CLAUDE_SKILL_DIR}/scripts/check-e2e-report.mjs . --app <game-id>` prints `RESULT: PASS`

## Anti-patterns

- **`tapOn: 'Play'` or `assertVisible: 'Level 1'`.** It breaks in German, Persian and Kurdish, and it breaks again whenever copy changes. Use `id: 'home.play-button'`.
- **Tapping Settings → Language → … to reach a state.** It is slow, and every screen change breaks unrelated flows. Use `debug-setup.yaml` with a `QUERY`.
- **`xcrun simctl openurl` for a debug link from a script.** iOS answers a custom scheme opened from outside with an "Open in <app>?" prompt that nobody accepts, so the app never gets the link (and the queued prompt hides the app from the next flow). Launch the app and run `debug-setup.yaml` through Maestro (`debugSetupArgs`), as the cold-start step does; `check-e2e-setup` fails `openurl` in the tooling (`openurl-prompt`).
- **`brew install maestro` or the `curl | bash` installer.** The version and checksum are unknown and analytics are on. Run `install-maestro.sh` (the runner calls it anyway).
- **Running on the `booted` simulator or a Debug build.** You may break another agent's device, and Metro's WebSocket makes the network check meaningless. Use the runner with a Release test build.
- **An `env:` block with `APP_ID` "so the flow runs on its own".** It overrides the runner's `-e` in 2.10.0. Pass `-e APP_ID=… -e APP_SCHEME=…` when running a flow alone.
- **`retry:` or a longer timeout to make a red flow green.** That hides a race the player will hit. Wait on the id that proves the state, or fix the app.
- **`--update` for every device and language, or a bigger `MAX_DIFF_RATIO`, to clear a diff.** That accepts regressions nobody looked at. Open the diff, fix the screen, and update only the sets you meant to change.
- **`assertNoDefectsWithAI` for "visual QA".** It uploads screenshots. Open the PNGs with the Read tool instead.
- **A "Simulate offline" switch that only changes what `isOnline()` returns, or a debug Premium switch that dispatches `premium-granted`.** Subscribers never hear the flip, and the save and the store disagree. Use `debugServices.setOffline` and `setPremium`.
- **`--write-perf-baseline` to clear a slower cold start.** That hides the regression. Find the start-up work that grew; a slower baseline needs the owner.
- **A shared sub-flow saved under `flows/`.** Maestro runs it on its own and it fails. Shared steps belong in `packages/shell/e2e/subflows/`.
- **A debug flag kept in a module variable or React state.** The direction reload and `killApp` drop it; keep it in `debug-services.ts`, which writes `debug.overrides` at once.
- **Reading a debug flag, the simulated day or a log straight from its service in S15's model.** An app build's React Compiler keeps the first value (verified: the offline switch stayed off, the perf summary stayed "empty"). Read them through `readDebugState(..., version)`.
- **A guard or a tap on a bare `'Open'`.** It also matches an ad banner's "OPEN" button; guard on Apple's alert title `'Open in .*\?'` (`open-alert-guard`).
- **Tapping a row right after `scrollUntilVisible`.** A tap while the list still glides only stops the scroll; add `waitForAnimationToEnd` first.
- **A second debug path for S15 (its own save writes, `navigation.navigate` to a jump target, `Alert` prompts).** Send the tool's request through `links.apply(request)`; ESLint bans `Alert`, so S15 uses the system action and share sheets.
