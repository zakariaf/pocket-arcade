# Build orders

Generated by `scripts/build-index.mjs` from `assets/index.json` and every skill's frontmatter. Do not edit it by hand: change the data (or a skill's description), then run `node ${CLAUDE_SKILL_DIR}/scripts/build-index.mjs --write`.

## Contents

- Running a "done when" check

- When npm run verify is green

Each layer is tested before anything depends on it: rules, then level generator, then save format, then services with fakes, then hooks, then screens, then end-to-end flows, then the screenshot matrix. A step starts only when the step before it passes its "done when" check. Every step is test-first (tdd-workflow) and ends in a commit and a short report (git-commits-and-reporting).

## Running a "done when" check

Every "done when" command runs from the repo root and is written out in full. A `<name>.mjs` command is the script `scripts/<name>.mjs` of the skill named after it in brackets: with that skill loaded, put `node` and the skill's scripts folder in front (inside the skill it is `${CLAUDE_SKILL_DIR}/scripts/`). The first argument `.` is the repo root: every checker takes the root as an optional positional argument and never as `--root`. `npm run ...` and `node packages/tooling/...` commands run as written. A check is done when it prints `RESULT: PASS`; `SKIP` lines and `NOT APPLICABLE` count as a pass, while exit 2 (nothing to check, bad input) never does. A step whose check cannot pass yet is not done: name it in the report with the reason. `SKIP` lines have exactly two causes: a screen outside `shell-slice.json` (`<S-id> not in shell-slice.json`), or a rule that is not yet due because a later step creates its target (`due at Shell step <n>: <file> not yet created`). Once that step creates the file the rule is strict, which is why steps 6, 7 and 8 rerun some earlier checks and expect no such SKIP line.

## A partial Shell: shell-slice.json

A repo without every Shell screen says so in `shell-slice.json` at the repo root: `{ "screens": ["S4", "S11", "S12"], "why": "Home + Settings parity slice" }`, with ids S1-S15 and S11a-S11d. `"screens": []` means a game-first repo with no Shell app; no file means the full Shell and every check is strict. While the file exists, every checker SKIPs (prints `SKIP <file> [<rule>] <S-id> not in shell-slice.json`, not counted) the rules of screens outside the slice, and the rules that need the Shell app itself when `screens` is `[]`; everything inside the slice is checked strictly. The route table never shrinks: a route whose screen is outside the slice points at `NotBuiltScreen` (navigation-and-routing), model hooks navigate normally, and a slice screen still routed to `NotBuiltScreen` fails. During the Shell build above: write `{ "screens": [], "why": "Shell build in progress: no Shell app yet" }` at step 1, change it to `["S1"]` when step 6 builds the splash and the navigator, add each screen id in the commit that builds that screen (step 9), and delete the file at step 10, once every screen is built (the release gates of step 11 fail while it exists). A slice built on purpose (a parity slice, a game-first repo) follows the same rules. Screens outside the slice have no route or view files, but the partial Shell core below is always there. To add the pilot's Game, Pause and Result to a slice that lacks them, follow "The pilot game into an existing Shell slice". **A slice never ships:** `check-navigation.mjs . --complete`, `check-game-app.mjs . --stage complete`, `check-release-setup.mjs .` and `check-store-artifact.mjs ... .` fail while `shell-slice.json` exists or any route uses `NotBuiltScreen`.

## When npm run verify is green

`npm run verify` runs its steps in order and stops at the first failure. Its runner (`packages/tooling/src/quality/run-verify.ts`, quality-gates) reads `shell-slice.json`: while the file exists, knip runs without its export and type issue kinds, and `test:sim` is skipped while no game has a `*.sim.test.ts`; each prints a `SKIP` line, and the last line counts them apart (`verify: 11 steps passed, 1 with SKIP lines`, or `verify: 10 steps passed, 1 skipped, 1 with SKIP lines` before the first sim), so a slice run never reads as clean; a run without the slice file ends `verify: 11 steps passed, 0 skipped`. Nothing uses `--passWithNoTests`. On the Shell build (with the slice file as above) the whole of `verify` is green from Shell step 8, and green with no `SKIP` line from step 10 (the slice file is deleted there). Before a step in the "Green from" column, the step below is expected red for the reason given; any other red step is a real failure.

| verify step | Green from | Before that |
|---|---|---|
| format:check, lint, typecheck, guardrail | Shell step 1 | never expected red |
| test:coverage | Shell step 1 | never expected red: every template ships a test or the `// device-only: covered by ...` marker (unit-and-component-tests); a red run names a file that lacks both |
| check-deps (`packages/tooling/src/deps/check-deps.ts`) | Shell step 1 | never expected red; an Expo patch younger than 7 days is a WARN that names its due date and fails from that date (dependency-management) |
| knip: files, dependencies, unlisted, binaries | Shell step 1 | never expected red (the knip template already ignores the tools spawned by name and the root mocks' native libraries) |
| knip: exports and types | Shell step 10 | exports that only a later layer uses; skipped with a `SKIP shell-slice.json [knip-exports]` line while shell-slice.json exists |
| test:sim | Shell step 3 | "No tests found" until the pilot's `*.sim.test.ts` exist; a `SKIP jest.sim.config.js [test-sim]` line while shell-slice.json exists |
| i18n:verify | Shell step 6 | `packages/tooling/src/i18n/verify-catalogs.ts` arrives with i18n-strings-and-catalogs; until then check-gate-wiring names it with --pending |
| audit:network, audit:licenses | Shell step 8 | `packages/tooling/src/audit/audit-network.ts` and the licence audit's bundle export arrive with the audit tooling of step 8; until then check-gate-wiring names the network audit with --pending |
