## What we will do

Build Shell step 5: the state stores and every service the screens will need, each behind its port with a device adapter, an in-memory fake and tests. Later epics only wire these parts; they never re-decide a rule.

- **The state stores.** Four domain stores (settings, progress, stats, Premium), each made by a factory over a pure reducer and created once by `createShellStores(save)`. Every change is reduced, saved, then published, so a screen never shows a value that is not on disk; a change that touches several sections goes through one `updateAndPublish` write. A run is a `GameSession` changed only by `gameSessionReducer`, saved before it is shown, restored paused.
- **Six new ports.** ConnectivityPort (expo-network, no HTTP probe), PurchasePort (expo-iap 5.8.0) with the Premium service, AdsPort (Google Mobile Ads 17.2.0, classic API), ConsentPort (Google's consent form and Apple's tracking prompt), HapticsPort (expo-haptics) and AudioPort (react-native-audio-api 0.13.6) with the sound synthesiser. With E04's three, all nine ports exist. Only an adapter imports its SDK.
- **The rules as pure, tested functions.** The spec 8.8 ad rules, the ad history, the perk offers (L11: a continue shows "loading" while its ad loads and is hidden only when no ad can come), the consent order (L10 and O1: the S3 intro only right before Google's form, then Apple's prompt while unanswered, then the ads SDK starts), the S12 Premium state machine (save before finishing, revoke only on a revocation date), the haptic throttle and the audio voice limits.
- **The ads switch (spec 4.3).** `ads-config.ts` replaces the bootstrap's phase-0 copy; `createAdsPort` and `createConsentPort` give an `ADS_MODE=off` build ports that never ask Google or Apple anything.
- **Nine packages**, each planned with `plan-dependency.mjs` and installed in the commit of its first importer, never earlier.

The order of the tasks follows the imports, so that every commit compiles on its own (the pre-commit hook runs the whole typecheck): the stores context imports the Premium store, so the Premium state comes first (T01); the ad gate imports the consent port, so it lands with consent (T08); the UI feedback imports the haptics port, so haptics (T09) comes before the audio adapter (T11).

**How a copied template is built test-first.** Almost every file here is copied from a skill's templates, tests included. Test-first still holds, one unit at a time: copy the unit's template test first; give every export it imports a typed stub that returns a wrong value (`return false`, `return []`, a method that does nothing); run `npx jest <test file> --ci --selectProjects unit` and keep the red assertion diff for the report (`Cannot find module` or a type error is not red for the right reason); then copy the template file byte for byte and watch the test go green. In the Build lines a template path is relative to the skill's `templates/packages/shell/src/` unless it starts with `__mocks__/` or `packages/`; it lands at the same path under the repo's `packages/shell/src/` (`__mocks__/` at the repo root, `packages/...` as written). Never rewrite a template from memory and never change a template test's assertions; adding new `it` cases is fine. Port files that hold only types have no test; their fakes and adapters prove them. A file marked `// device-only: covered by <check>` is proven by that check, run red against a stub first in the same way (T05 does this for the expo-iap adapter).

No task in this epic builds or changes a screen, so no task has a "Design match" line. The screens these services feed are built and matched to their Toybox frames later: S3 (`s3-consent-moment`, `s3-google-s-form`) in E11, the banner slots on S4, S8 and S10 in E12 and E13, and the S12 states (`s12-premium`, `s12-loading-price`, `s12-store-unavailable-offline`, `s12-purchase-in-progress`, `s12-pending-approval`, `s12-success`, `s12-error`, `s12-already-owned`, `s12-restore-results-toasts`) in E15.

## How we work in this epic

1. Branch: `git switch main && git pull && git switch -c epic/e05-services-and-stores` (leave out `git pull` when the repo has no remote). Push the branch after each task, but only once the owner has allowed pushes (git-commits-and-reporting rule 5), and only through the pre-push hook. At this build step that hook's `npm run verify` cannot pass yet: it stops at `i18n:verify` (red until E06), and `audit:network` and `audit:licenses` stay red until E10. So the hook refuses the push. Never bypass it: keep the commits local and say so in the report.
2. Test first, always. Write each task's "Tests first" items, run them and watch them fail for the right reason, write the minimum code to pass, then refactor. Never weaken or edit a test to make it pass. For the copied templates follow "How a copied template is built test-first" above. No path this epic touches is gated, so a trailer appears only if a fix needs one. `npm run -s check:fast` must be green before every commit.
