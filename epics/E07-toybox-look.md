## How we work in this epic

1. Branch: `git switch main && git pull && git switch -c epic/e07-toybox-look`. Push the branch after each task (`git push -u origin epic/e07-toybox-look`). Two limits apply: a push needs the owner's word in the session (git-commits-and-reporting rule 5), and the pre-push hook runs `npm run verify`, which stays red at `audit:network` until Shell step 8 (E10). If either stops the push, keep the commits local and say so in the report; never bypass the hook (`--no-verify`, `LEFTHOOK=0`).
2. Test first, always. Write each task's "Tests first" items, run them and watch them fail for the right reason, write the minimum code to pass, then refactor. Never weaken or edit a test to make it pass. Most units here come with a template and its test: copy the test file first and run it; when it fails on a missing module, write a typed stub of the unit that returns a wrong value (a component that renders `null`, a function that returns `0`) until the failure is an assertion diff (`Expected ... Received ...`), then copy the template over the stub. Copy templates, never retype them, and keep their values.
3. Commit each task in Conventional Commits form, with the trailers the skills ask for (Gate-Change:, Spec-Change:). `npm run -s check:fast` must be green before every commit. Check each message first with `node skills/git-commits-and-reporting/scripts/check-commits.mjs . --message reports/commit-message.txt --staged`. Scopes here are `shell`, `line-siege`, `tooling` and `deps`.
4. Screens: a task that builds or changes a screen is not done until toybox-visual-parity's capture matches the Toybox design screenshot for every frame it names, in light-en, light-fa, dark-en and dark-fa at every scroll offset, and check-signoff passes for those frames.
