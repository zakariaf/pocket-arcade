Pocket Arcade · design system for the Shell (every screen except the game board)

Toybox

Every Pocket Arcade game is a small toy: a wall of blocks under siege, a tilting field of sheep, a junkyard of clumsy robots. Toybox dresses the Shell like the shop shelf those toys sit on: chunky plastic keys with one thick ink outline, hard shadows that a finger pushes the key into, and die-cut stickers for anything worth celebrating. Each game only repaints the shelf, so twenty-six apps feel like one family.

Raised means you can press itButtons, tiles and keys cast a hard 3-6pt shadow and sink into it when pressed. Panels that only hold information lie flat.
One ink, many paintsOutline, text and shadow are the same ink in every game. A game swaps three paints: ground, accent, pop. Shapes never change.
Stickers carry newsStreaks, new bests, Premium, locks and test builds arrive as tilted stickers with a white die-cut ring. Everything else sits square.
Shape before colourStars are filled or hollow, locked tiles are dashed with a padlock, toggles show a check or a dash. Colour only confirms.

Avoids

  • Soft blurred drop shadows, glass and backdrop blur
  • Gradient fills on buttons or cards: every paint is flat
  • Pill buttons: the biggest control radius is 14pt
  • Fills without an ink edge, which melt into the ground
  • White or cream screen grounds: the ground is always a painted wash
  • Emoji and clip-art: icons are one 24-unit path each
  • Centred screens: text starts at the start edge; only splash and result stars are centred
  • Tilted body text: only stickers rotate, never more than 8°

Implementation notes for React Native

How Toybox maps onto the stack in docs/05 and docs/10: typed theme, logical start/end layout, Skia icon paths, bundled fonts.

Theme module

Each game ships one Palette (standard and colour-blind, light and dark). Toybox fills the existing ColorTokens and adds five fields the Shell needs for its shape language. Add them once in theme-types.ts (N5), then every game fills them.

  • background = ground, surface, text, textMuted, primary = accent, onPrimary, border = outline, danger, icon, starOn, starOff.
  • New: sunken, pop, onPop, shadow, focus. Gold, the sticker cut and the ad neutrals are Shell constants, not game paint.
  • tokens.ts: SPACING stays {2, 4, 8, 12, 16, 24, 32}; RADII becomes {xs 6, sm 10, md 14, lg 22}; add STROKE {hair 2, tile 2.5, bold 3} and ELEVATION {tile 3, control 5, hero 6, dialog 8}; MIN_TOUCH stays 44.
  • TYPE_SCALE: display 38, title 30, heading 21, body 17, label 17 bold, caption 13, plus a number role (30, display face) for stats.

      

      

        
Shape, press and icons

        
    
          
  • Hard shadow: not iOS shadowRadius or Android elevation, which blur. RaisedSurface draws a sibling View in shadow colour, offset down by the elevation, under the control. Pressing animates translateY to the elevation and scales (1.03, 0.94) with Reanimated, then springs back (damping 12, stiffness 420).
    • 
          
  • Outlines are borderWidth: 3 in border. Dashed states use borderStyle: 'dashed'.
    • 
          
  • Stickers are a View with transform: [{ rotate }] and a second View 3.5pt larger in the cut colour behind it (the white die-cut ring).
    • 
          
  • Icons: authored as 2.5-unit strokes plus fills on the 24 grid shown above. A build script turns each one into a single fill path (SkPath.stroke(), then MakeFromOp(…, Union)) and writes icon-paths.ts, so the docs/05 Icon rasterizer and tintColor pipeline stays as it is. The lock keyhole uses the even-odd rule; the build calls simplify() to make it nonzero. DIRECTIONAL_ICONS = back, chevron, forward, undo.
    • 
          
  • Logos, result stars, how-to-play pictures are Skia canvases (at most 8 per screen). The pattern on the S15 hazard strip is the only repeating fill, drawn once by Skia.
    • 
          
  • Targets: every control is at least 44 × 44 pt. Keys are 48-94 pt tall, level tiles 51 × 62 pt, toggles sit in 60 pt rows so the whole row is the target.
    • 
        

      

      

        
Fonts (bundled, SIL OFL 1.1)

        
    
          
  • Lilita One Regular (LilitaOne-Regular.ttf, ~40 KB): display, titles, headings, numbers, big buttons. It has one weight, so never set fontWeight on it. It covers German ä ö ü ß.
    • 
          
  • Rubik Regular and Bold (static Rubik-Regular.ttf, Rubik-Bold.ttf cut from the variable font): body, labels, captions. It fills the LATIN_SCRIPT entries in docs/10 fonts.ts, which are platform fonts today.
    • 
          
  • Vazirmatn 33.003 Regular and Bold: all fa and ckb text. Lilita roles map to Vazirmatn-Bold, Rubik roles to Regular or Bold. Line height is 1.5 × size (display 1.45).
    • 
          
  • Latin line height: 1.1 for display roles, 1.3 for text. Game names stay in Lilita One in every language, isolated with FSI…PDI.
    • 
          
  • Add Lilita One and Rubik to the S11d font rows (the mockup already shows them).

Contrast, checked

        
WCAG 2.2 ratios computed from the palette data on this page. Body text is AA (4.5:1) or better everywhere. Accent fills are weaker against the light grounds (about 1.8:1), so every accent fill carries the 3pt ink outline, which is 11:1 or more against the ground.
